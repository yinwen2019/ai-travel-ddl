## 已确认的产品行为

| 项目 | 用户确认的行为 | 本轮数据状态 |
|---|---|---|
| 城市举办榜 | 继续展示本站历史实体会议举办届次 | 从现有只读 JSON 真实派生 |
| 会议热度榜 | 用户显式主动点击会议对象，每次 `+1`，全部累计 | 尚未接入全站采集，不展示虚构次数或名次 |
| 城市热度榜 | 用户显式主动点击城市对象，每次 `+1`，全部累计 | 尚未接入全站采集，不以本机数据冒充全站数据 |
| 城市期待榜 | 表达“希望这座城市承办会议”；同城可反复累计 `+1`，不取消，不限制为一人一票 | 本机累计预览，明确当前浏览器范围 |
| 首页支持 | 爱心连续点击，每次累计 `+1`，带反馈动效 | 本机预览，不是全站支持总数 |

热度不设置 2 秒停留门槛、不按日去重、不按 7 天或 30 天等周期切换；同对象的真实重复点击分别增加。期待和支持不设置每日 10 次或其他产品额度。异常速率保护只用于处理机器洪泛，不得把正常连续点击改成“一人一天一票”。

首页右侧四榜轮播；导航使用英文 `Rankings` 进入完整榜单。每榜注明真实来源与数据范围。本机期待和支持持久化失败时继续本次浏览并提示；通过清除浏览器站点数据可重置本机预览，没有取消期待或页面重置入口。本机累计不自动迁移成全站数据。

## 计数对象、单位与排序

- 城市举办榜继续按 REQ-C19，只统计 `type=history` 的实体届次，排除线上与未来届次，单位“届”。
- 会议热度按 `conference.id` 汇总，同一会议跨年份合并，单位“次点击”。
- 城市热度按城市目录稳定 `city.id` 汇总，复用现有城市合并规则，单位“次点击”。
- 城市期待按城市稳定 ID 累计每次明确的承办期待，单位“票”，同一访客可反复加票；不从访问量推断期待，不称为独立人数。
- 支持使用独立项目计数，不与城市期待、会议或城市热度混为同一个指标。

同数保留真实并列名次，内部按实体名称稳定排序；零次期待的城市仅作为候选，不生成排名。全站统计正式启用后从零开始，并注明开始时间及最近更新时间；不回填不存在的历史点击，不把总次数称为真实用户数。

## 哪些动作计入热度

原则：**一次显式主动的实体激活动作，最多生成一个对应实体的热度事件。真正再次点击是新事件；组件渲染或状态变化不是事件。**

| 用户动作 | 热度处理 | 事件归属 |
|---|---|---|
| 会议标题、历届详情、关联会议、会议榜单等实体链接 | 每次主动激活 `+1` | 只计对应会议 |
| 会议官网外链 | 每次主动激活 `+1` | 只计对应会议，不额外计卡片或举办城市 |
| 首页城市榜单、城市目录、会议卡片或地图面板中的城市链接 | 每次主动激活 `+1` | 只计对应城市，不计父会议 |
| Ctrl / Cmd 点击、鼠标中键打开实体链接 | 每次主动激活 `+1` | 在来源页上报；目标新标签不再加一次 |
| 链接或原生按钮通过 Enter / Space 激活 | 与浏览器原生等价点击一致 | 通过原生 `click` 统一处理，不再另绑按键重复计数 |
| 地球城市点、年表城市定位按钮、城市选择器的明确用户选择 | 每次主动选择 `+1` | 对应城市；一次选择带动地图和面板只算一次 |
| 表格会议列头的明确会议选择 | 每次主动选择 `+1` | 对应会议；地图视角随之变化不再上报 |
| 同对象重复点击，包括重复打开同一城市或官网 | 每次分别 `+1` | 每次新动作生成新事件 ID |
| 城市承办期待按钮、首页支持按钮 | 不增加热度 | 只增加各自独立互动指标 |
| hover、曝光、滚动、搜索、筛选、切年、轮播、缩放、复位、暂停 | 不计 | 浏览工具或状态变化 |
| 路由挂载、刷新、直接输入地址、后退恢复、自动跳转或程序恢复选择 | 不计 | 没有站内显式实体点击；目标页不得补计 |
| 独立关闭面板、清除选择、右键打开上下文菜单 | 不计 | 不是实体激活 |

关闭同一地球点的直接再次点选仍是用户点击该城市对象，可计一次；独立关闭按钮不计。筛选会议的复选框仍是筛选工具，不因标签包含会议名称而计热度。

右键菜单中的“在新标签页打开”通常没有可可靠观测的页面实体激活事件，本方案不通过目标页挂载猜测补计。中键和 Ctrl / Cmd 点击由来源事件覆盖。统计解释应说明它是站内可记录的主动点击总量，不是所有访问量。

## 集中计数入口

### 链接与普通按钮

建议使用集中 `click` / `auxclick` 监听器，对明确标记或可验证的会议、城市入口解析实体：

1. `click` 接收主键或原生键盘激活；`auxclick` 仅处理中键，过滤右键。不要另在 `keydown`、`pointerdown` 和目标页挂载重复加分。
2. 沿事件路径定位最近的真实实体操作入口；官网链接显式标明会议 ID，站内详情链接按稳定路由解析或标明实体 ID。
3. 一次动作只确定一个归属：城市链接只计城市，官网只计会议。不要在父卡片、父行与子链接分别绑定累加。
4. 每次真实动作创建新的 `eventId`，调用同一统计服务。网络重试沿用原 `eventId`；用户再次点击必须创建新 ID。
5. 新标签由来源页上报，采用适当的保活提交及有界重试；不阻断原生导航，不用目标页生命周期兜底重复计数。

前端可过滤程序合成事件，但这不是服务端真人认证。记录失败不能阻止用户正常浏览。

### 地球、表格与选择器

Canvas 地球点选、表格实体定位和城市选择器由各自的**明确用户动作处理器**调用相同统计服务，传入实体与来源。`selectedCity` watcher、路由恢复、地图飞行、面板挂载或渲染回调不得上报。

若某个表格按钮已经进入集中 DOM 监听器，就不能在业务处理器再调用一次；适配层必须指定单一负责人。地图点选由一次输入引起多个状态变化时，只在输入入口创建一次事件。自定义键盘入口调用同一适配器，避免“按键处理一次、随后原生 click 再一次”。

## GitHub Pages 与数据架构边界

REQ-B01 既有范围是构建时导入会议静态 JSON、无后端 API；三层解耦铁则继续适用于会议数据：

```text
src/       → 只读消费会议与城市 JSON
data/      → 纯静态会议与城市数据
scripts/   → 维护 data/，不访问 src/
```

用户已确认后续引入**独立互动统计域**，不代表修改会议数据层或本轮创建云资源。不能为点击榜改写 `data/conferences.json`、`data/locations.json`、历史会议条目或既有数据更新脚本。统计代码、存储和部署需与静态会议数据隔离。

GitHub Pages 无法提供运行时服务端执行环境来接收点击并修改部署中的 JSON。浏览器存储无法形成所有访客共享的统计。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

已确认的后续架构方向：

```text
GitHub：代码、会议与城市静态 JSON
    ↓ GitHub Actions
GitHub Pages：Vue 站点
    ↓ 主动点击事件 / 读取公共累计榜单
Cloudflare Worker：校验、网络重试幂等、异常速率保护
    ↓ 私有绑定
D1：实体累计点击、承办期待、项目支持
```

前端只公开 API 地址等公共配置。密钥与数据库访问留在服务端；不提供前端数据库写权限，不把秘密放在 `VITE_*` 变量。本轮保留热度未开启状态，等待后续实际接入。

### 不逐次写入 GitHub

仓库文件 API 写入需要 `Contents: write` 权限、提交信息及被更新文件 SHA，还存在竞争更新和请求限流。每次点击都提交仓库会污染历史并放大部署开销，不适合作为实时计数数据库。仓库写令牌不能交给浏览器。[仓库文件 API](https://docs.github.com/en/rest/repos/contents)、[GitHub API 限制与密钥说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)

可选每日导出一次仅含匿名聚合总数的 JSON 快照到 GitHub，供备份或静态降级；不得包含匿名浏览器标识、IP 或逐次点击明细。这不是实时数据库，是否启用快照仍是后续实施选择。

## 建议 API 与存储实现

下列实现细节服务于已确认的累计口径，接口路径与内部保留期限仍可在服务实现时调整，不新增用户日配额。

| 接口 | 用途 | 约束 |
|---|---|---|
| `GET /v1/rankings?board=...` | 公共累计榜单 | 榜单白名单；可缓存 60 秒，返回开始及更新时间，不提供周期参数 |
| `POST /v1/clicks` | 一次会议或城市点击 | 实体类型、稳定 ID、事件 ID、来源；服务端最多执行 `+1` |
| `POST /v1/cities/:cityId/expectations` | 一次城市承办期待 | 每次真实点击新事件；允许同城重复，不提供取消或 toggle 接口 |
| `POST /v1/support` | 一次项目支持 | 每次真实点击新事件；连续累计，无产品日额度 |

服务端校验随部署同步的实体 ID 清单，复用稳定城市 ID；不接受任意总数、任意增量或伪造实体。建议用累计表保存每实体总数，短期幂等表仅以 `eventId` 唯一，不建立“浏览器＋实体＋日期”的去重约束。

幂等记录与累计更新必须一起成功：并发收到同一事件只加一次，收到两个不同真实动作则加两次。D1 批处理可作为事务执行，失败时回滚整批；具体 SQL 必须保证只有首次有效事件才推进汇总。[D1 批处理说明](https://developers.cloudflare.com/d1/worker-api/d1-database/)

不使用 KV 的 `get → +1 → put` 直接维护总数：并发写入可能覆盖，且同键每秒最多写一次。[KV 并发写入说明](https://developers.cloudflare.com/kv/api/write-key-value-pairs/)

## 异常保护与隐私

- 匿名 ID 仅用于异常速率观察与防刷，不是独立人数，不限制一人一票或真实重复点击。
- 保留基础异常速率保护，主要处理明显机器洪泛；阈值在后续接入时依据正常连点节奏设定，不设置每日 10 次等业务上限，不把正常连续支持或期待拦成重复投票。
- 数据库保证事件幂等与累计准确；Worker 速率绑定是最终一致的软保护，不能充当精确计数账本。[Worker 速率限制精度](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)
- CORS 限定生产与明确开发来源，但不能替代验证，也不能阻止脚本伪造请求。若后续出现异常洪泛，可评估 Turnstile；需服务端验证，不将挑战设为阻碍正常连点的默认行为。[Turnstile 服务端验证](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)
- 不保存姓名、邮箱、搜索词、完整浏览 URL、设备指纹或原始 IP。必要的异常限流只使用短期带盐摘要，并限制日志内容；匿名摘要仍按假名数据处理。
- 建议短期幂等事件保存 7 天，有界网络重试不得超过该窗口；过期队列应丢弃或以旧事件过期处理，不能换 ID 重放。累计总数独立保留，不随明细清理减少。
- 开发、视觉预览和自动化测试不向正式数据写入事件。本机历史默认不上传，不把此前的浏览器计数转成全站真人统计。
